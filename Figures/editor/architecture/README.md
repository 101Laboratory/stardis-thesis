## 设计意图

以自顶向下的分层方框图展示 StardisEditor 的三层模块划分及层间依赖关系。重点表现：（1）交互层通过 Model-View 模式读写中间数据模型层；（2）工具层负责 DSL 文本与语义模型的双向转换及外部求解器调用；（3）交互层不直接接触 DSL 序列化——round-trip 发生在工具层与数据模型层之间。

## 模块层次（来自表 tab:gui:modules）

| 层次 | 主要类 | 职责 |
|------|--------|------|
| 交互层 | `SceneEditor`、`SceneTreePanel`、`PropertyPanel`、`SceneViewport`、`SurfacePainter` | 主窗口编排、层级树/属性面板/3D 视口投射、画笔标注交互 |
| 数据模型层 | `SceneModel`、Task 数据对象（`StardisParams`、`HtppParams`、`Camera`、`Probe`）、任务队列 | DSL 语义模型、仿真任务与观测数据、队列调度状态 |
| 工具层 | `SceneParser`、`SceneWriter`、`CommandBuilder`、`TaskRunner` | DSL 具体语法 ↔ 语义模型双向转换、CLI 参数组装、子进程执行 |

### 关键标注

1. **交互层（顶层）**：`SceneEditor` 作为主窗口容器，内含三个并列面板，均通过信号/槽读写数据模型层的 `SceneModel`。`SurfacePainter` 附属于 `SceneViewport`（画笔模式子组件）
2. **数据模型层（中间层）**：`SceneModel` 是核心数据源（橙/金色突出），持有 DSL 全部语义数据。Task 数据对象和任务队列并列放置。工程文件 `.stardis_project.json` 以虚线框表示编辑器扩展状态
3. **工具层（底层）**：左侧 `SceneParser`/`SceneWriter` 负责 DSL 文本与语义模型的双向转换（round-trip 发生在此层与模型层之间）；右侧 `CommandBuilder`/`TaskRunner` 负责 CLI 参数组装与子进程执行
4. **交互层不直接接触序列化**：面板仅读写 `SceneModel`，由工具层的 `SceneWriter` 负责将模型序列化回 DSL 文本
5. **外部实体**：DSL 文件和 Stardis/HTPP CLI 进程置于工具层下方，以灰色框表示

## 制图建议

- 推荐用 draw.io / TikZ / SVG 制作
- 纵向自顶向下排列三层，每层以横向色带背景区分
- 层间箭头标注数据方向（"读写 SceneModel"、"解析/序列化"、"CLI 参数/子进程"）
- 实线箭头表示数据依赖，虚线箭头表示信号/槽通知
